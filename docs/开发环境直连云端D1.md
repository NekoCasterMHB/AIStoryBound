# 开发环境直连云端 D1 — 实现指南（供 AI / 开发者接手参考）

> **目标读者**: 需要在本仓库（或类似 NuxtHub + Cloudflare Workers 项目）中实现「本地 `pnpm dev` 直接读写**云端** D1/R2，而不是本地模拟数据」的 AI 代理或开发者。
>
> **一句话原理**: 在 `wrangler.toml` 给 D1/R2 binding 加 `remote = true`（Cloudflare **Remote Bindings**），NuxtHub 的 dev 代理（`wrangler.getPlatformProxy()`）就会在本地开发时通过 Cloudflare API 直连真实云端资源；部署后 `remote` 字段被忽略、始终使用 Worker 真实绑定，**开发/生产代码路径完全一致**。

---

## 1. 背景与目标

- 默认情况下，本地开发（`nuxt dev` + `getPlatformProxy`）会用 **Miniflare 本地模拟** D1/R2，数据落在 `.wrangler/state`，和线上完全隔离。
- 本项目希望本地开发时直接读写**线上** D1/R2（例如需要真实邮件发送、真实数据调试、多人协作共享同一份数据）。
- 要求：**不改业务代码**、不引入 API Token 到源码、不改变生产行为。

## 2. 方案总览

```
pnpm dev
  └─> Nitro cloudflare dev 插件
        └─> wrangler.getPlatformProxy()
              └─> 读取 wrangler.toml
                    ├─ remote = true  ──> Cloudflare API ──> 云端 D1 / R2
                    └─ (无 remote)     ──> 本地 Miniflare ──> .wrangler/state
              └─> 绑定注入 globalThis.__env__
                    └─> server/utils/bindings.ts (getDB / getR2)
                          └─> 业务代码（同一套代码路径）
```

## 3. 前置条件

| 条件 | 说明 | 验证命令 |
|------|------|----------|
| 已安装 `wrangler`（本项目 `^4.118.0`） | 提供 `getPlatformProxy` 与 Remote Bindings | `npx wrangler --version` |
| **已登录 Cloudflare 账号** | Remote Bindings 需要 wrangler 登录态（OAuth token）或 `CLOUDFLARE_API_TOKEN` 环境变量，**不需要在源码/配置里写任何 Token** | `npx wrangler whoami` |
| 云端 D1 数据库已创建 | 数据库名与 `wrangler.toml` 一致 | 见下方第 6 节 |
| 云端 R2 存储桶已创建 | 存储桶名与 `wrangler.toml` 一致 | `npx wrangler r2 bucket list` |

> ⚠️ 若 `wrangler whoami` 未登录，`remote = true` 会静默退化为本地模拟或报错。这是最常见的「直连没生效」原因。

## 4. 关键配置清单

### 4.1 `wrangler.toml`（核心开关）

```toml
[[d1_databases]]
binding = "DB"
database_name = "clouddrive-db"
database_id = "3ba3fa06-562e-46f1-b554-5976f94a26be"
remote = true   # ← 关键：本地 dev 直连云端 D1

[[r2_buckets]]
binding = "R2"
bucket_name = "clouddrive-files"
remote = true   # ← 关键：本地 dev 直连云端 R2
```

要点：
- `remote = true` 只影响**本地开发代理**，部署时该字段被 Cloudflare 忽略，生产始终用真实绑定。
- D1/R2 的 `binding` 名必须与代码中读取的键一致（本项目统一为 `DB` / `R2`）。
- `database_id` 必须在 Cloudflare Dashboard 中与该数据库真实 ID 一致。

### 4.2 `nuxt.config.ts`

```ts
hub: {
  db: {
    dialect: 'sqlite',
    driver: 'd1'          // 通过 @nuxthub/core 生成基于 env.DB 的 Drizzle 实例
  },
  blob: false
},
nitro: {
  preset: 'cloudflare_module',
  cloudflare: { deployConfig: true, nodeCompat: true }
}
```

- `deployConfig: true` 会让 Nitro 把 `wrangler.toml` 同步为部署配置。
- `hub.db.driver = 'd1'` 决定 `@nuxthub/db` 暴露的 Drizzle 实例对接 D1 binding。

### 4.3 `server/database/index.ts`（数据库入口）

```ts
export { db } from '@nuxthub/db'
```

统一通过 D1 binding 获取 Drizzle 实例，本地/生产零差异。

### 4.4 `server/utils/bindings.ts`（绑定读取）

- 通过 `globalThis.__env__`（开发由 `getPlatformProxy` 注入，部署由 `fetchHandler` 注入真实 env）统一获取绑定。
- 提供 `getBindings()` / `getDB()` / `getR2()`，业务层不感知来源差异。

```ts
export function getDB(): any {
  const env = getBindings() // 内部读 globalThis.__env__
  return env.DB
}
```

## 5. 主方式：`pnpm dev`（推荐，日常开发）

直接运行：

```bash
pnpm dev
```

- NuxtHub 的 cloudflare dev 插件自动调用 `wrangler.getPlatformProxy()`，检测到 `remote = true` 后直连云端 D1/R2。
- 业务代码、Drizzle 查询、R2 读写全部走真实云端数据。
- 优点：开发体验与生产一致，可热更新，无需单独起 worker。

## 6. 备用方式：`pnpm dev:remote`（`wrangler dev --remote`）

当不想依赖 Nuxt dev server 的代理、或需要以纯 Worker 形态验证线上行为时使用：

```bash
pnpm dev:remote   # 等价于 wrangler dev --remote
```

- `wrangler dev --remote` 直接以 **remote 模式**启动 Worker，D1/R2 绑定天然指向云端。
- 与主方式的差异：走的是 `wrangler dev` 本地 HTTP server（默认 `http://localhost:8787`），**不是** `nuxt dev` 的 `http://localhost:3366`；更适合接口级调试 / 验证真实线上行为。
- 该方式下同样需要 wrangler 登录态。

> 使用建议：日常前后端联调用 `pnpm dev`；需要「纯 Worker 视角 + 真实云端数据」验证时用 `pnpm dev:remote`。

## 7. 数据库结构初始化（云端）

直连云端后，表结构需要用 `server/db/init.sql` 初始化（唯一权威源，幂等，本地/云端通用）：

```bash
# 云端 D1
npx wrangler d1 execute clouddrive-db --remote --file=server/db/init.sql
# 本地 D1（仅当你想退回本地模拟时）
npx wrangler d1 execute clouddrive-db --local --file=server/db/init.sql
```

- 数据库结构以单个初始化脚本 `drizzle/init.sql` 为唯一权威源（全量 schema，所有语句 `IF NOT EXISTS` 幂等，本地/云端通用，可重复执行）；应用命令即 `pnpm db:migrate:remote` / `pnpm db:migrate:local`（内部执行 `wrangler d1 execute aiSpankWorld <target> --file=drizzle/init.sql`）。schema 变更时同步手工维护该文件（见其头部注释的约定），不再使用 `drizzle-kit generate`。
- 参考：`drizzle.config.ts` 中的注释即上述说明。

## 8. 排查清单（直连没生效时）

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 数据写在本地、线上看不到 | `remote = true` 缺失 | 确认 `wrangler.toml` D1/R2 段已加 `remote = true` |
| 报错「Cloudflare bindings 不可用」 | 未通过 `pnpm dev` 启动（如直接 `node` 跑） | 必须走 `pnpm dev` / `pnpm dev:remote` |
| 认证失败 / 401 | 未 `wrangler login` 或 Token 失效 | 运行 `npx wrangler whoami` 确认登录态 |
| 数据库不存在 / 表不存在 | 云端 D1 未建库或未执行 init.sql | 见第 7 节 |
| `database_id` 不匹配 | 数据库 ID 与云端不一致 | 在 Dashboard 核对 ID |

## 9. 给 AI 实现者的检查清单

实现完成后，请逐项确认：

- [ ] `wrangler.toml` 中 `[[d1_databases]]` 与 `[[r2_buckets]]` 均带 `remote = true`
- [ ] `npx wrangler whoami` 已登录（能访问目标账号）
- [ ] 运行 `pnpm dev` 后，新建一条数据，能在 Cloudflare Dashboard 的 D1（`clouddrive-db`）里直接看到（而不是只在 `.wrangler/state`）
- [ ] 上传一个文件，能在云端 R2（`clouddrive-files`）看到对象
- [ ] 部署（`pnpm build` + deploy）后行为不受影响（`remote` 被忽略，走真实绑定）
- [ ] 未在源码 / 配置中硬编码任何 Cloudflare API Token

> 上文为通用方案（面向 NuxtHub 项目）。本仓库**不是** NuxtHub 项目，落地时按下列实际差异执行：

### 已完成的改动

1. **`wrangler.toml`**：仅给 `[[d1_databases]]`（binding `DB`）加了一行 `remote = true`。本项目没有 R2 binding（小说正文走静态资源 `[assets]`），所以不存在 `[[r2_buckets]]` 段。
2. 未改动任何业务代码。本仓库的 D1 访问统一经 `server/utils/d1.ts` 的 `getD1Binding()` / `useD1()`（先读 `event.context.cloudflare.env.DB`，再回退 `globalThis.__env__.DB`），开发代理注入方式不变，`remote = true` 在 wrangler 代理层生效，对应上文 4.4 节。
3. 上文 4.2/4.3 节（`hub.db` / `server/database/index.ts`）为 NuxtHub 专属，本仓库**不适用**，忽略即可。
4. **云端库已就绪**：全部 16 张表已建齐（`pnpm db:migrate:remote` 应用 `drizzle/init.sql`，幂等可重复执行），`preset_novels` 有 12 条预置数据（`pnpm db:migrate:remote` / `pnpm seed:presets:remote` 维护）。
5. `package.json` 新增备用脚本 `pnpm dev:remote`（`nuxt build --preset cloudflare_module && wrangler dev --remote`），对应上文第 6 节。

### 生效前提与验证

- 需要 wrangler 登录态：`npx wrangler whoami`（本项目已登录，OAuth，w2575525962@gmail.com）。
- `pnpm dev` 启动日志出现 `⎔ Establishing remote connection...` 即直连生效。
- **改了 `remote = true` / 登出登录后要重启 dev server**（`nitro-cloudflare-dev` 在启动时缓存代理配置）。
- 已实测：`pnpm dev`（端口 4569）下 `GET /api/presets` 返回的 12 条数据与 `wrangler d1 execute aiSpankWorld --remote` 逐字段一致，而本地 Miniflare 模拟库（`.wrangler/state`）连 `preset_novels` 表都没有 —— 确认 dev 已直连云端 D1。

### 退回本地模拟的方法

临时把 `wrangler.toml` 里的 `remote = true` 去掉（或注释），重启 `pnpm dev` 即回到 Miniflare 本地库；本地库用 `pnpm db:migrate:local` + `pnpm seed:presets:local` 初始化。
