# 作品格式 v2(aisb-book)设计文档

> 状态:设计定稿(待实施)· 本文件是后续 P0-P6 每个阶段的验收基准
> 关联事故:外部/异版本导出的 `aisb-share v1` zip 中人物卡 `appearance` 为结构化对象、`personality` 为字符串,
> 与当前 `CharacterCard`(appearance:string、personality:string[]) 不兼容,导入后在选角页 `c.appearance?.trim()` 崩溃。
> 结论:**存储/交换层必须"向后容忍、向前可扩",展示层不得假设字段存在且类型正确。**

---

## 1. 背景与动机

### 1.1 问题根因

- 当前人物卡 `CharacterCard` 是**固定类型化 schema**(英文键 + 强类型),生成管线靠"AI prompt 约定"产出,
  但**只在生成边界内强制**;导入 zip / 读取历史数据时**零校验、零归一**,schema 变更也不升分享包版本号。
- 结果:新版/异版产出(结构化外观对象、字符串性格、驼峰字段)进入旧版消费端 → 运行期崩溃,书卡在半路。

### 1.2 v2 的目标

1. **向后容忍**:任何来源的人物数据读进来不崩(值形状不苛求,归一化兜底)。
2. **向前可扩**:新版本/作者可自由加属性,旧版本不识别也不炸(自由区 + 动态渲染)。
3. **贴近作者心智**:人物键名用中文、键即文档;人物卡按实际数据动态渲染。
4. **按段自包含**:情节每段一个文件,段与段可独立移动/增删/同步。

## 2. v2 容器规范(aisb-book)

```
书名.book2.zip
├── manifest.json          # 格式标识 + 版本 + 元信息
├── fulltext.txt           # 全文一份(仅供阅读器/整本成书/分享阅读)
├── plot/
│   ├── 000.json           # 分段 0
│   ├── 001.json           # 分段 1
│   └── …
└── characters/
    ├── 何清玲.json         # 人物 1
    ├── 班主任.json
    └── …
```

### manifest.json

```jsonc
{
  "format": "aisb-book",          // 固定
  "version": 2,                   // 结构变更必须升版本
  "kind": "book",
  "title": "资料室之行",
  "author": "佚名",                // 可选
  "plotCount": 12,
  "charCount": 3,
  "tags": ["淡向", "现实"],        // 可选:书架卡/选角页展示用
  "orientation": "不明",           // 可选:性向
  "heat": "淡",                    // 可选:尺度 淡/中/烈
  "setting": "现实校园…",          // 可选:舞台一句话
  "exportedAt": "2026-09-02T08:02:57.792Z"
}
```

> `version` 语义:人物卡契约/plot 契约/目录结构任一变化 → 升 version;旧消费者读到 `version > 自己支持` 时提示"请升级"。

## 3. plot 段 JSON 契约(已锁定)

```jsonc
// plot/000.json
{
  "index": 0,                      // 段序(排序键)
  "title": "第1段",                // 段标签(可选)
  "cast": ["何清玲", "班主任", "保安"],   // 出场人物;值必须与 characters/ 下某文件的「姓名」一致
  "beat": "细纲:班主任交代任务,何清玲前往资料室…",  // 情节细纲
  "place": "办公室、职工区",        // 可选:场景
  "turn": "开端",                  // 可选:起承转合
  "hook": "结尾钩子",              // 可选
  "人物状态": {                    // 可选:本段各人物的状态/覆盖(见 §5)
    "何清玲": { "身份": "学生，学习委员", "处境": "受老师信任" }
  },
  "text": "「报告!」\n\n　　「进。」\n…"    // 被切段的原文(内联切片,段自包含)
}
```

设计取舍(已定):

- **原文内联**:段内直接带 `text` 切片,自包含、可独立移动/增删/重排;代价是大长篇全文冗余 2-3 倍,
  `fulltext.txt` 单独一份供阅读器与整本成书,不参与段间引用。
- **cast 对齐**:出场人物名必须与 `characters/` 下的「姓名」一致(关联锚),拼写不一致视为该段无此人登场。

## 4. characters JSON 契约(已锁定)

```jsonc
// characters/何清玲.json
{
  // —— 保留键(中文,AI/作者必须生成;值形状容忍,见 §4.1)——
  "姓名": "何清玲",                 // string,关联锚(cast/关系/游戏状态/文件名)
  "角色": "主角",                   // 结构锚:主角/配角/反派(引擎搭框架用,见 §7)
  "身份": "学生，学习委员",
  "外貌": "高挑,黑色长发…",
  "性格": ["认真", "有责任感"],     // string[] 或 string(容忍)
  "背景": "班主任信任的学习委员…",
  "目标": ["完成老师交代的任务"],
  "关系": [                         // 跨人物引用:对象 = 另一人物「姓名」
    { "对象": "班主任", "值": 75, "说明": "关系较为亲近" }
  ],

  // —— 可选保留键(按需填)——
  "别名": ["学习委员"],
  "性欲强度": 40, "耐心": 60, "心软": 80,   // 数值|null
  "玩法喜好": [{ "主题": "打屁股", "态度": "接受", "角色": "承受", "细节": "…" }],
  "成人属性": { "体位": "…", "习惯": "…" },  // 自由对象
  "首次出场": "第3段",
  "已死亡": false,

  // —— 完全自由区(任意键任意值,见 §6)——
  "家庭背景": "单亲,跟母亲生活",
  "癖好细节": "怕痒",
  "口头禅": "好的老师"
}
```

### 4.1 值容忍规则

- **"必须生成"只约束键存在,不约束值形状**。
- 引擎读取统一经「保留键解释器」(§7)做归一:字符串/数组/对象都接受,
  数组→必要时合并为文本、字符串→必要时按 `、，,;；\n` 拆分、`null`/缺失→视为空。

### 4.2 保留键宽度(已定:全语义保留,玩法不回退)

| 保留键 | 类型约定 | 引擎用途 |
|---|---|---|
| 姓名 | string,必填 | 关联锚:cast/关系/游戏状态/配角弧线 |
| 角色 | 主角/配角/反派 | 结构锚:主叙事视角/徽章(仅 `主角` 有程序分支) |
| 身份/背景/外貌 | string|null | prompt 人物定位 |
| 性格/目标/别名 | string[] 或 string(容忍) | prompt 性格/目标 |
| 关系 | [{对象,值(-100~100),说明?}] | 亲密度 + 正向关系判定 |
| 性欲强度/耐心/心软 | number|null | 数值化行为参数(欲望初始化/脾气/妥协) |
| 玩法喜好 | [{主题,态度?,角色?,细节?}] | 题材玩法注入 |
| 成人属性 | 自由对象 | 成人向属性注入 |
| 首次出场 | string|null | 出场段 |
| 已死亡 | boolean|null | 死亡标记 |

## 5. 按段演化:状态放 plot 段内(已定)

- **人物卡只存跨段不变的基础设定**;某段特有的身份转变/处境/状态写在 `plot/NNN.json` 的 `人物状态` 里。
- 引擎在进入第 N 段时:取该段 `人物状态[姓名]`,与基础卡做**浅覆盖**(值缺失继承基础卡)。
- 替代现 `CharacterCard.chapterVariants` + `effectiveCard` 机制;段与状态同生共死,改段不牵连人物卡。
- 跨段快速浏览某角色轨迹:后续可用索引/工具汇总(开放问题)。

## 6. 动态渲染与编辑规格(已锁定)

### 6.1 选人卡片 / 书架人物卡(展示)

- 保留键 → 富展示:姓名/角色徽章/身份/外貌/性格(标签式)/背景/关系网计数…
- 自由键 → 通用"键:值"渲染:
  - 字符串 → 文本;数组 → 标签/多行;数字 → 数字;布尔 → 是/否;对象 → 子分组缩进
  - 结构化对象(如异版本外貌 `{身高,build,…}`)→ 展开成"键:值"子行,**不崩、可读**
- 折叠:所有字段默认显示 1 行,超长截断省略号;点击展开/收起。

### 6.2 编辑(人物卡编辑器)

- 保留键 → 富控件:文本域(自动增高,默认 1 行)/标签式增删/关系行编辑器/数值滑块或输入框。
- 自由区 → "＋ 添加字段":
  - **键名自由输入**(中文),重复/占用保留键时提示;
  - **值显式选择类型**:文本(单行)/文本(多行)/列表/数字/开关/对象;
  - 已有自由键随时可改键名/类型/删除。
- 外来/未知结构(导入的 zip 里的怪字段)→ 按通用渲染展开,**可编辑不崩**。

## 7. 保留键解释器与引擎读取层(设计方向,实施时细化)

- 文件/交换层用中文键;引擎(shared/game.ts 等)内部语义用现字段名。二者经**边界解释器**转换:

```
中文保留键(文件)  --解释器-->  引擎语义字段
  姓名        -->  name
  角色        -->  role
  身份        -->  identity
  外貌        -->  appearance
  性格        -->  personality[]
  背景        -->  background
  目标        -->  goals[]
  关系        -->  relationships[{name,type,value}]
  性欲强度/耐心/心软 --> desire/patience/softness
  玩法喜好/成人属性  --> kinks/sex
  首次出场/已死亡    --> first_appearance/dead
```

- 解释规则:
  1. 命中保留键 → 归一后映射;
  2. 其余键 → 全部并入 `profile`(自由区对象);
  3. 引擎 prompt:`cardBrief` 末尾追加「补充设定:…」(profile 的紧凑 JSON),保证新字段不丢给 AI。
- 值容忍统一在解释器实现(§4.1),**消费端不再各自 `.trim()`/`.join()` 假设类型**。

## 8. 转换器与兼容策略(已定:双格式可导,不强制迁移)

- **旧 aisb-share v1(work.json)→ v2**:章节全文 → `fulltext.txt` + 按细纲/字数切段 → `plot/`;
  `overlay.characters`/`entities.characters` 归一 → `characters/`(英文键 → 中文保留键,未知字段 → 自由区)。
- **v2 → 旧模型(可选回读)**:老功能/老引擎临时读取路径。
- 旧 zip **永久可导入**(转换器),新导出默认 v2;存量 IndexedDB / D1 / 云端备份**不强制一次性迁移**,
  读取时经转换器进新模型,需要持久化时落 v2。
- 所有导入统一过「归一化层」(沿用现有 `normalizeCharacterCard` 思路并扩展为中文键解释器),**杜绝脏数据进运行态**。

## 10. 风险与开放问题(实施时逐项定)

1. **配角弧线挂载**:建议 `characters/何清玲.arc.json`(或角色文件内嵌 `弧线` 键),P4 与生成一起定。
2. **云端 D1 预置小说 / 创意工坊**:novels 表列结构(world_state JSON)与 v2 的关系——预置世界是否 v2 化,还是"预置仍旧格式 + 进书架时转换",P5 定。
3. **阅读器全文组装**:阅读/整本成书走 `fulltext.txt`;分段阅读如需逐段滚动,按段偏移展示。
4. **体积上限**:plot 内联原文 + fulltext 双份 → 导入/同步上限需评估(参考现有 64MB zip 上限)。
5. **保留键覆盖规则**:作者/新版本若把保留键写成非预期结构(如 `性格` 是对象),解释器降级为"并入补充设定"而非崩溃;具体降级清单 P2 定。
6. **`角色` 结构锚的演进**:多主角/主角戏份转移作品,`主角` 判定是否要引入"主角权重"或多主角标记,P2 结合引擎框架逻辑定。
