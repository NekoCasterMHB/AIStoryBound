## 最终实施计划(预授权扣费 + 验证指纹 + 强制测试 + 限流)

**1. `server/api/ai/chat.post.ts` — 平台模式"预授权 + 流尾多退少补"(核心)**
- 转发前原子预扣:`reserve = estimateMessagesTokens(messages) + maxTokens 预留`(客户端传了用其值,未传默认 16384,统一 ≤32768);`UPDATE user SET ai_token_balance = ai_token_balance - reserve WHERE id = ? AND ai_token_balance >= reserve`,影响行数 0 → 402"余额不足以预扣本次调用预估消耗"。同时关闭"余额 1 无限白嫖"与"并发超卖"两个洞。
- 流尾 `waitUntil` 结算:`balance = MAX(balance + reserve - cost, 0)`,多扣退还、超耗补扣;`aiUsage` 仍按真实 cost 记录,统计口径不变。
- 预扣成功后、上游请求前的任何失败(连接失败/非 2xx)先退还预扣再抛错。
- 正常体验不受影响:世界生成并发 4 单元 ×(≈1 万 prompt + 1.6 万预留)≈ 10.5 万在途 < 注册赠送 30 万,预扣调用结束即释放。

**2. 用户模式(自建 key)格式与指纹双重准入**
- 格式约束:baseUrl 强制 `https://`,长度钳制(baseUrl ≤512 / apiKey ≤256 / model 必填 ≤128);`maxTokens` 服务端钳制 1~32768(两模式统一)。
- **验证指纹准入**:新建小表 `ai_config_verifications`(user_id、fingerprint、verified_at,user_id 索引,每用户滚动保留 5 条兜底)。`/api/profile/ai-config/test` 测试成功时计算并落库指纹:HMAC-SHA256(密钥由 BETTER_AUTH_SECRET 派生),覆盖 `userId|format|baseUrl|apiKey|model`——改任何一项都需重新测试。`/api/ai/chat` 用户模式先算请求 config 的指纹比对库内记录,不命中 → 400"配置未验证或已变更,请重新测试",不扣费、不回退平台 key。免计费通道只对服务端验证过的配置开放,可撤销、可管控。
- 用户模式上游失败仍直接 502,绝不回退平台 key(补注释明确)。

**3. 新增 `server/utils/rate-limit.ts` — 通用限流工具**
- 抽取 redeem.post.ts 的进程内 Map 滑窗逻辑为公共函数(按 key+窗口+次数),`redeem.post.ts` 与 `test.post.ts` 改用它;test 端点限每用户每分钟 5 次,超限 429。注释注明 per-isolate 局限。

**4. `server/db/schema.ts` + `drizzle/init.sql`**

**5. `app/pages/profile.vue` — 配置上限 5 条 + 保存/启用前强制连接测试**
