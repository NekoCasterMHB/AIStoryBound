# IndexedDB 迁移到 Dexie.js 计划

## 背景与目标

当前项目用 `idb`（`app/utils/localDb.ts` 的 `db()`）管理 IndexedDB，118 处操作散布在 9 个文件。开发期反复改 `DB_VERSION`（v4→v9）导致多标签页 versionchange 互堵，已手写补丁（自关 + 失败重置 + 超时）。迁移到 Dexie.js 后这些连接管理由库内置，schema 变更改为声明式，不再手写 upgrade 回调。

**已确认**：Dexie 默认在 `versionchange` 时自动关闭旧连接（官方文档明确），这正是我们手写补丁做的事——迁移后手写逻辑可删，堵塞根因从库层面消除。

---

## 1. 安装依赖

- `pnpm add dexie`
- 可选 `dexie-react-hooks`（本次不用，项目无响应式绑定需求）

## 2. 重写 `app/utils/localDb.ts`（核心）

从 idb 的 `openDB` 封装改为 Dexie 子类，schema 声明式：

```ts
import Dexie, { type Table } from 'dexie'

export class AIStoryBoundDB extends Dexie {
  worlds!: Table<WorldRow, string>          // keyPath: 'novelId'
  saves!: Table<GameSavePoint, string>       // keyPath: 'key'
  presets!: Table<CachedPreset, string>      // keyPath: 'id'
  works!: Table<LocalWork, string>           // keyPath: 'id'
  games!: Table<LocalGame, string>           // keyPath: 'id'
  reading!: Table<ReadingProgress, string>   // keyPath: 'key'
  'ai-skills'!: Table<AiSkill, string>       // keyPath: 'key'
  'toy-settings'!: Table<{ key: string }, string>  // keyPath: 'key'
  'toy-adapters'!: Table<ImportedPluginRecord, string> // keyPath: 'id'
  prefs!: Table<{ key: string }, string>     // keyPath: 'key'
  'extract-cache'!: Table<ExtractCacheEntry, string> // keyPath: 'key'

  constructor() {
    super('aiSpankWorld-local')
    this.version(9).stores({
      worlds: 'novelId',
      saves: 'key',
      presets: 'id',
      works: 'id',
      games: 'id',
      reading: 'key',
      'ai-skills': 'key',
      'toy-settings': 'key',
      'toy-adapters': 'id',
      prefs: 'key',
      'extract-cache': 'key'
    })
  }
}

export const db = new AIStoryBoundDB()
```

**迁移要点**：
- 库名保持 `aiSpankWorld-local`、版本号 9、所有 store 名与 keyPath **完全不变** → 现有 IndexedDB 数据零迁移直接可用
- Dexie `version(9).stores()` 只声明字段名，`'key'` 表示主键；**数据保留**，不像 `dropTables`/`upgrade` 清库
- 删掉手写的 `onversionchange` 自关、`.catch` 重置——Dexie 内置
- `STORE_*` 常量保留导出（调用方仍用），但内部实现全换

**关键风险点**：Dexie 的 `version().stores()` 若 store 不存在会**创建空表**；已存在的 store 若声明缺失字段不会删数据，仅当**移除整个 store** 才会丢。本次 11 个 store 全部保留，无数据风险。

## 3. 逐文件迁移调用方（9 个文件）

idb API → Dexie API 对应关系：
| idb | Dexie |
|---|---|
| `(await db()).getAll(store)` | `await db.table(store).toArray()` |
| `(await db()).get(store, key)` | `await db.table(store).get(key)` |
| `(await db()).put(store, val)` | `await db.table(store).put(val)` |
| `(await db()).delete(store, key)` | `await db.table(store).delete(key)` |
| `(await db()).clear(store)` | `await db.table(store).clear()` |
| `d.transaction(store, 'rw')` | `db.transaction('rw', db.table(store), ...)` |

各文件：
- `worldGen.ts`（works 表，6 处）
- `gameStore.ts`（games 表，4 处）
- `gameSaveStore.ts`（saves 表，7 处）
- `readingStore.ts`（reading 表，4 处）
- `presetStore.ts`（presets 表，4 处）
- `aiSkills.ts`（ai-skills 表，4 处）
- `narrSpeed.ts`（prefs 表，2 处）
- `toy/store.ts`（toy-settings / toy-adapters，7 处）
- `extractCache.ts`（extract-cache 表，5 处 + transaction 1 处）

**保留**：每个文件 `typeof indexedDB === 'undefined'` 的 SSR 守卫（Dexie 在服务端会抛错，守卫不变）；`JSON.parse(JSON.stringify(...))` 剥离 reactive 代理的写法不变；`withDbTimeout` 超时兜底保留（Dexie 打开也可能被外部连接阻塞，超时是双保险）。

- 不重命名 store / 不改 schema 结构（保持数据兼容）
- 不迁移 `localStorage`（aiSkills 的启用开关、genSettings 等仍走 localStorage，与 IndexedDB 无关）

## 风险与回退

- **数据风险极低**：库名/版本/store 名/keyPath 全部不变，Dexie 只接管不迁移数据
- 若迁移中发现异常：`git` 回退即可（纯替换，无数据层不可逆操作）
- 唯一注意：`version(9).stores()` 里任何 store 名拼错会建新空表而非报错——用现有 11 个 store 常量逐个核对
