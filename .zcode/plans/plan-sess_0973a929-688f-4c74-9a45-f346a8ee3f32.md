## 目标

让 Better Auth 的 baseURL 自动适配当前请求域名,彻底移除手动配置 `BETTER_AUTH_URL` 的负担(本地、生产均自动正确),同时保留显式配置作为可选覆盖手段。

## 原理

better-auth 的 baseURL 解析优先级为:显式配置 → 环境变量 `BETTER_AUTH_URL` → 每请求从 Host header / 请求 URL 自动推断。本项目前后端同域部署,推断结果天然正确,因此只需清空所有显式值即可。Better Auth 实例虽被缓存(`cachedAuth`),但 baseURL 推断发生在每次请求处理时,缓存不影响动态适配。

## 改动

### 1. `server/utils/auth.ts`(核心)
- 第 6 行头注释:更新为「未显式配置时自动按请求域名推断」
- `AuthEnvConfig.baseUrl` 改为可选 `string | undefined`
- `getAuthConfig`:删除兜底 `'http://localhost:4567'`,改为 `baseUrl: env?.BETTER_AUTH_URL || rt.baseUrl`(两者都没配时为 `undefined`,触发 better-auth 请求推断)
- `createAuth` 的 `baseURL: cfg.baseUrl` 保持不变(传 `undefined` 即走推断路径)

### 2. `nuxt.config.ts`
- `runtimeConfig.auth.baseUrl` 默认值 `'http://localhost:4569'` 改为 `''`,并更新第 56 行注释:说明未配置时自动适应请求域名,本地 dev 自动为 `localhost:4569`

### 3. `.dev.vars`
- 删除 `BETTER_AUTH_URL=http://localhost:4567` 行(附注释说明域名自动适配)

### 4. 保留覆盖能力(不改逻辑)
- env 与 runtimeConfig 的读取优先级链原样保留:未来若前后端分离部署等场景需要,仍可显式设置 `BETTER_AUTH_URL` / `NUXT_AUTH_BASE_URL` 覆盖

## 附带收益

- 修复现有隐藏不一致:`.dev.vars` 的 4567 与 devServer 端口 4569 不一致(此前邮件/回调链接端口错误),移除后自动正确
- 生产部署无需再在 `wrangler.toml` 或 Cloudflare dashboard 补配 `BETTER_AUTH_URL`(当前生产端正是缺口状态)

## 风险

- better-auth 推断依赖请求 Host header,正常浏览器访问均携带正确 Host;仅在未来「非 HTTP 请求上下文生成链接」(如定时任务发邮件)的场景才需要显式配置,届时用现有 env 覆盖即可
