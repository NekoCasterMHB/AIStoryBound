### 方案：差异不再代码定稿——收集全部版本描述，成书阶段交给 AI 合并出完整人设

**核心思路**：合并阶段对"可并存文本字段"（身份/外貌/背景）不再"后文覆盖前文 + 记冲突"，而是**原样收集该角色在不同章节的全部不同表述**；生成人物卡（成书）时把这些版本 + 冲突裁决一起交给成书 AI，由它判断哪些并存、哪些矛盾，输出**一套完整、自洽的最终人设**。零新增 AI 调用（复用本来就有的成书调用）。

**1. 合并阶段改为"收集版本"（`shared/world-build.ts` mergeExtractions）**
- `identity` / `appearance` / `background` 不再走 `mergeScalar`（不记冲突、不覆盖），改为收集去重版本列表（归一化去重 + 互相包含时保留更长的），存入实体新字段 `identityVariants` / `appearanceVariants` / `backgroundVariants`（`shared/novel.ts` 的 `MergedCharacter` 加可选字段）。
- 实体本体字段仍保留最后一次的值（chapterVariants 快照、eco 本地拼卡等现有逻辑不受影响）。
- `gender` / `age` / `dead` 等互斥标量维持现状（记冲突 + 后文为准）。

**2. 成书阶段交给 AI 合并（`buildSynthesizeMessages`）**
- 每张卡的输入带上 `identityVariants` / `appearanceVariants` / `backgroundVariants`。
- **已知冲突摘要补上 `valueA` / `valueB` 具体值**（现在只给 verdict 和 reason，模型看不到冲突内容是什么）。
- 新增指令："同一角色在不同章节的多版本身份/外貌/背景与已知冲突：相互兼容的描述整合为一套更完整的设定（可并存的都保留，如既是留学生又是作家），互斥的按裁决结论取信；输出一套自洽的完整人设，不要在卡里罗列多个版本。"

**3. 节约模式兜底（`buildLocalCards`）**
- eco 不跑成书 AI，用代码把版本列表简单拼接兜底（identity `/` 连接、background `；` 连接、带长度上限），同样不丢信息。

**4. 游玩 prompt 冲突注入小修（`shared/game.ts` plotTrackBlock）**
- 注入前过滤 `verdict === 'not_conflict'` 再取前 5，已判"非冲突"的条目不再占用游戏内裁决位（对已生成旧作品也生效）。

**边界说明**
- 冲突列表从此只含真互斥矛盾（性别/年龄/生死类），身份/背景差异不再灌水；
- 只影响今后新生成的作品，已落库数据不回改。

**验证**：脚本构造两段提取（同角色 identity 两值、background 互补两句、gender 相异）跑 `mergeExtractions`，断言 variants 收集齐全、无 identity/background 冲突、gender 冲突仍在；`buildSynthesizeMessages` 输出含 variants 与 valueA/valueB；lint + typecheck。
