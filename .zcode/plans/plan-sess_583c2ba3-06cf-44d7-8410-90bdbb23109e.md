# 每小时充值健康检查 + 仪表盘显示充值开放状态

## 现状

- 无任何 cron 基础设施：`entry.cloudflare.mjs` 只导出 fetch + WorldGenWorkflow，`wrangler.toml` 无 `[triggers]`。
- 充值开关：`app_config` 表 `payment_disabled`（`server/utils/config.ts`，`'1'`=维护），读写工具齐备；管理端充值页 `/admin/recharge` 已有开关切换。
- 充值链路：`getMicropayConfig`（env 优先）→ `signRSA` → 网关；`scripts/query-order.mjs` 已演示网关查询的自检写法（签名 + POST，无副作用）。
- 仪表盘：`server/api/admin/dashboard.get.ts` + `app/pages/admin/index.vue`，已有「AI 配置生效状态」卡片可直接复用展示风格。

## 改动

### 1. `wrangler.toml` — 注册 cron
```toml
[triggers]
crons = ["0 * * * *"]
```

### 2. `entry.cloudflare.mjs` — 导出 scheduled handler
```js
export async function scheduled(event, env, ctx) {
  ctx.waitUntil(runRechargeHealthCheck(env))
}
```
（`env` 自带 `DB` 与 `MICROPAY_PID / MICROPAY_PRIVATE_KEY`。）

### 3. 新建 `server/utils/recharge-health.ts` — 核心检查
`runRechargeHealthCheck(env)`：
1. **配置检查**：缺 `MICROPAY_PID` 或 `MICROPAY_PRIVATE_KEY` → 失败。
2. **网关连通检查**：复刻 `query-order.mjs`——`generateOutTradeNo()` → `buildSignStr` + `signRSA` 签名 → `POST https://pay.microgg.cn/api/pay/query`，HTTP 2xx 即链路通（查询无副作用）；网络异常/非 2xx → 失败。
3. **状态翻转**（直接写库，等价 `/api/admin/recharge/config`）：
   - 失败 && 当前开放 → `setAppConfig(db,'payment_disabled','1')`（进维护）
   - 成功 && 当前维护 → `setAppConfig(db,'payment_disabled','0')`（恢复开放）
   - 状态未变化不写
4. `console.log` 记录结果与翻转，供 wrangler logs 排查。

### 4. 仪表盘显示充值开放状态
- `server/api/admin/dashboard.get.ts`：读取 `isPaymentDisabled(db)`，返回 `paymentDisabled: boolean`。
- `app/pages/admin/index.vue`：新增「充值开放状态」卡片（放在「AI 配置生效状态」旁/前）：
  - 开放 → 绿色徽标「充值开放」+ 说明「用户可正常下单充值」；
  - 维护 → 红色/琥珀徽标「充值维护中」+ 说明「由每小时健康检查自动切换或管理端手动设置」；
  - 附跳转「充值管理」入口（/admin/recharge）。

### 5. 不改
网关回调、订单表、`payment/create`、admin 充值接口、兑换码通道全部不动；不建测试订单（避免每小时累积 pending 单）。

## 行为矩阵

| 检查结果 | 当前状态 | 动作 |
|---|---|---|
| 失败 | 开放 | 置为维护 |
| 失败 | 维护 | 保持 |
| 成功 | 维护 | 恢复开放 |
| 成功 | 开放 | 保持 |

## 验证

- eslint / typecheck（先 `pnpm install` 恢复 dexie 链接，此前已修复）。
- `runRechargeHealthCheck` 用 mock env 跑三态翻转单测/脚本验证。
- 仪表盘手动刷新看状态徽标；部署后 `wrangler logs` 看每小时记录。
