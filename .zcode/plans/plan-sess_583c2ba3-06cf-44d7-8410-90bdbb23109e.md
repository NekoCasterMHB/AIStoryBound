# 云端世界生成工作流优化(按已确认的选择执行)

## 1. 提速:author 并行 + parse/plan 合并(并发 4→8 不做)
- `world-gen-pipeline.ts` 新增 `stepParseAndPlan(ctx)`(parse + plan 两个纯代码步合成一个,少一个 workflow step 与 DB 往返)
- `server/workflows/world-gen.ts` + 内联兜底:先 parseAndPlan,然后 **author-ai 与第一批提取单元并发**(Promise.all),后续批次照旧;author 结果写入逻辑不变

## 2. 一致性检查保留 + 提示词优化
- 保留 check 步骤(核实它确实参与情节统一:裁决已有冲突 + 发现遗漏新冲突,流入成书与游戏设定裁决)
- `shared/world-build.ts` `buildCheckMessages` 增加两条裁决规则:
  - 近义/同义改写不算冲突(只有事实性矛盾才判冲突)
  - 同一人物可有多个身份/称谓/别名/伪装:关系链里反复出现的同一人(不同身份标注)应识别为同一实体,不算冲突

## 3. 弧线生成注入登场段原文窗口(忠实度增强)
- `buildCharacterArcMessages`(+批量版)增加可选 `textWindow` 参数:注入该角色登场段的原文节选,模型基于原文细节写戏份
- 窗口计算统一在服务端:取候选角色**前 3 个登场段**、每段从 `startChar` 起 **2500 字**(越界/缺失跳过注入)
- arcs 任务 payload 增加 `text`(客户端上传全书文本,`chapters.join('\n')`);world-gen 成书模式用 `deriveUnits` 从 R2 原文取同口径窗口

## 4. 弧线两套合一:成书也走逐单元
- `stepSupplementArcs` 支持两种来源:`kind==='arcs'`(payload)与 world-gen 成书模式(merged 实体/细纲 + R2 原文)
- 成书管线移除 `stepCharacterArcs` 批量调用,统一走 `stepSupplementArcs`(成书自带逐条进度、失败可续跑);批量 `buildCharacterArcsMessages` 保留(scripts/prebuild-presets.ts 仍用,不动 prebuild)
- workflow/内联:world 任务在 synthesize 后、finalize 前执行该步骤(仅 full 模式,与现状一致)

## 5. 查重合并进上传接口(省一次往返)
- `upload.post.ts`:算出 hash 后查共享缓存——命中且未带 `forceRegenerate` 时**不建任务**,返回 `{ task: null, cacheHit }`;带 `forceRegenerate=1` 或未命中时照常建任务
- `generate.vue`:移除独立的 `/check` 调用与确认页预展示;点「开始生成」上传后,若返回 cacheHit 弹「拉取(半价)/重新生成」选择框——拉取走现有 pull 接口,重新生成带 forceRegenerate 重传
- `/api/world-gen/check` 接口保留(兼容),客户端不再调用

## 6. 砍掉浏览器端本地生成编排
- `generate.vue`:删除 `runGeneration`/`retryGeneration`(失败态"继续生成")/本地生成分支;本地作品与预置小说的确认页「开始生成」统一走云端(从章节文本构造 File 复用上传流程);失败态引导改为提示云端任务区操作
- `app/utils/worldGen.ts`:删除 `generateWorld` 及其专属本地编排辅助(逐个确认无其它调用方后清理;`parseLocalNovel`/`toContentSegments`/`isLegacyChapteredWork` 等共享函数保留;`GenerateProgress` 类型保留供云端任务进度映射)
- `app/utils/extractCache.ts` 整文件删除(clearExtractCache 调用点同步清除)
- 自建 key 用户不受影响:云端上传/弧线任务已支持自建 key(AES-GCM 加密暂存、任务结束即删)

## 7. 验证
