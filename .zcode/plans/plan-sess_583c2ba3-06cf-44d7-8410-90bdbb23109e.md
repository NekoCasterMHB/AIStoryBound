## ToyController 多连接架构改造(多启用 → 多连接)

### 目标
从「单连接槽位」改为「每插件一连接」：多个已启用插件可各自保持独立连接(真机或模拟)，AI 指令/手动控制按插件 id 路由到对应设备；游戏页叙事流升级为支持多设备同时驱动。

### 1. 传输层工厂化(app/toy/transports/)
- **web-bluetooth.ts**：模块级单例 → `createWebBluetoothTransport()` 工厂，每实例独立 `pickedDevice / knownDevices / currentChar / disconnectHandlers`；`batteryCache` 与 localStorage 已授权缓存保留模块级(按设备 id 全局无妨)。`ToyTransport` 接口不变。
- **mock.ts**：`mockTransport` 单例 → `createMockTransport()`，每连接独立 `writeLog / connected` 状态；保留 `mockTransportState` 导出给 ToyConfigModal 日志展示(或改由 slot 提供)。
- 现有 `webBluetoothTransport / mockTransport` 导出名改为工厂函数；调用点更新。

### 2. ToyController 核心重构(app/toy/api.ts)
- **state** 从单值改为 `{ connections: Record<adapterId, ToyConnectionState> }`；`ToyConnectionState` = 现有 ToyControllerState(connected/adapterId/adapterName/deviceName/deviceId/transportId/functions/autoActive)。
- **私有槽位** `slots: Record<adapterId, Slot>`，Slot = `{ adapter, transport, timers, waveTimers, wavePrev, waveTargets, waveRuns, waveStopTimers, unregisterDisconnect }`——波形/计时器全部按连接隔离。
- **方法**：
  - `connect(adapter, transport, opts)` 不变(内部按 adapter.id 建 slot；可同时存在多个连接)；
  - `disconnect(adapterId?)`：缺省断全部，带 id 只断该连接；
  - `slotOf(id): ToyConnectionState | undefined`、`connectedIds(): string[]`；
  - `execute(raw, opts)`：路由改 `raw.adapter` 缺省 = opts.targetId(调用方显式指定)，未连接目标返回明确拒绝；`stopAll/emergencyStop` 按 slot 遍历；`beginAutoSession/endAutoSession` 按 slot。
  - 删除悬空的 `toyFnStatus`(无调用方)或改签名带 adapterId。
- 保留单例导出 `toyController`。

### 3. shared/toy.ts 设置命名空间
- `ToySettings.aiEnabledFunctions / functionLimits` 键改为 `${adapterId}:${fnId}`(多设备同名能力分别限制)；
- `checkHardLimits` 增加 adapterId 参数解析命名空间键；`validateDeviceEvent` 透传 adapter 不变。

### 4. 游戏页多设备 AI(games/[id].vue + narrStream.ts)
- **narrStream.ts**：`NarrToken` 增加 `adapter?: string`；`[[dev:插件id:功能:强度…]]` 语法——解析时首段非数字即视为插件 id 前缀(与 PluginTestModal 同一宽容逻辑)。
- **shared/game.ts**：`narratorDeviceSpec` 指令语法升级为「可带插件 id 前缀」；描述不变(已含 id)。
- **games/[id].vue onExecute**：按 `cmd.adapter` 路由——`toyController.slotOf(cmd.adapter)` 对应连接执行；无 adapter 缺省当前 active 连接；`describePlugin` 的 connected 按 slot 判定。

### 5. 消费方适配(6 组件 + profile)
- **SchemaControlPanel.vue**：改用 `toyController.slotOf(props.spec.descriptor.id)` 读 functions/connected/autoActive；execute/startWave/stopWave 带 adapterId。
- **ToyConfigModal.vue**：按 `props.pluginId` 读 slot；连接/断开/电量/手动控制都走该 slot；移除「已连接则跳过」单槽守卫。
- **ToyQuickConnectModal.vue**：删除 `ensureFreeSlot()`(不再先断开其它)；连接目标 = props.adapterId。
- **ToyControlStrip.vue**：遍历 `toyController.connectedIds()` 显示多设备徽标；target 定位改为显式(当前 active 或列表选择)。
- **PluginTestModal.vue**：`connectedSpecs` 改为「启用且已连接」= 遍历 slots；执行已带 adapter 前缀，适配新路由。
- **profile.vue**：`isConnectedTo(id)` 改读 `slotOf(id)?.connected`；删除适配器时只断该适配器连接(不再全局断)。
- **games/[id].vue** 注入部分按 §4。

### 6. 兼容与验证
- 手动控制、测试模态框、游戏页三路径全部回归；多插件同时连接互不干扰(同名功能按 adapter 隔离)；切换/断开单个连接不影响其它。
- eslint + typecheck；dev 用 mock 连接两个插件验证并行执行与独立波形。

### 不做(本轮)
- 同一插件多设备同时连接(每插件一连接)。
- 传输层 BLE 底层多实例的浏览器兼容性专项(Web Bluetooth 本身支持多 GATT，按 Chrome 行为)。
