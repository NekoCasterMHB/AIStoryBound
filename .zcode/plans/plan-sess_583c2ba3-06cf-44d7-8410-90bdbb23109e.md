# 「本回合 N tokens」点击弹统计模态框（饼图 + 细分项）

## 目标

点击顶部「本回合 xxxx tokens」→ 弹出「本回合 token 消耗」模态框，用两个环形饼图 + 图例解释消耗构成，让用户理解「几百字对话为什么上万 token」。

## 数据

- **大项**（叙事 / 选项收尾 / 开局性欲初始化）：用真实 `RelayedUsage`（prompt/completion/total，已归一化）；失败重试并入该大项合计。
- **输入细项**（叙事 prompt 内部 8 项）：用 `estimateTextTokens` 按字符估算 token 与占比，标注「按字符估算」。

## 展示清单

### 阶段饼图（真实 usage 占比）
1. 叙事生成(正文流式)
2. 选项与状态收尾
3. 开局性欲初始化（仅首回合实际调用时出现）

### 输入构成饼图（估算占比，9 扇区）
输入 8 项：
1. 系统规则与内容政策（成人政策 + 基础规则 + 设备联动）
2. AI 技能规则（启用技能的 SKILL.md 全文注入）
3. 用户偏好与回避场景
4. 角色卡与人设（玩家卡 + 其他卡 + 人设提醒重贴）
5. 游戏状态（状态 JSON + 动态状态）
6. 世界设定与剧情轨道（题材/背景 + 故事线 + 世界 + 伏笔 + 裁决 + 段回注）
7. 剧情回顾与历史消息（摘要 + 最近 12 条 + 开局/开场提醒）
8. 玩家本轮行动
输出：
9. 正文

每项仅在**实际包含**时显示（未启用技能则无第 2 项等）。

## 改动点

### 1. `shared/game.ts`
- 把 `buildTurnPrompt` 重构为「先收集带标签片段，再 join」：新增 `buildTurnPromptParts(args): { label, content }[]`，将现有 `rules` 数组拆成三组带标签片段（基础规则 / skillRules / prefer+avoid），拼接顺序与结果不变；
- 新增 `estimateTurnPromptBreakdown(args)`：对每个 part 用 `estimateTextTokens` 返回 `{ label, tokens, pct }[]`；`buildTurnPrompt` 返回结构不变。

### 2. `app/pages/games/[id].vue`
- 新增 `turnCostReport = ref<TurnCostItem[] | null>`（`TurnCostItem = { stage, label, prompt, completion, total, details? }`）与 `costModalOpen = ref(false)`；
- `sendTurn` 开头清空；`seedDesiresByOpening` 成功时 push 大项；叙事成功后用 `estimateTurnPromptBreakdown` push 叙事大项 + 细项；`runOptionsPhase` 成功后 push 选项大项 + 细项；
- 显示区（1098-1101）span 改为可点击，点击打开模态框；
- 新增 `UModal`（复用 statModal 的 `sm:max-w-md!`）：
  - **阶段消耗环形饼图**（conic-gradient，中心显示合计）+ 图例；
  - **输入构成环形饼图**（9 扇区）+ 图例（色块 + 名称 + token + %）；
  - 底部解释文案「每次 AI 调用都携带完整上下文作为输入,输入远大于输出,因此几百字对话也会消耗上万 token」；
  - 环形图由 `conic-gradient` 拼字符串生成（预置色板循环，值 ≤0 跳过），零依赖；
- 关闭/新回合/回滚时随 `turnUsage` 一起清空。

## 不改

- `typewriter.ts`、`narrStream.ts`、计费落账（`addWorkTokens`/`recordTaskUsage`）；
- `turnUsage` 字符串保留（数字口径与模态框合计一致）。

## 验证

- eslint 通过；手动走一回合（含首回合带开局 + 启用技能）：点「本回合 N tokens」弹窗，两个饼图渲染正确、大项合计 == `turnUsage` 总数、细项占比与估算一致；开关/回滚后清空。
