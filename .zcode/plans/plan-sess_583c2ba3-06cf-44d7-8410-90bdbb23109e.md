## 云端生成任务计费改造:成功才扣费 + 移除旧预扣结算 + 未结算不进缓存

### 现状
- 新任务 `reserveTaken=0`,`recordTaskUsage` 每个 AI 单元成功后**逐笔原子扣余额**,不足 → `InsufficientTokensError` → `paused`(断点续跑)。
- `settleTaskBilling`(reserveTaken=1 旧预扣任务退差额)在 4 处调用全是空转。
- `stepFinalize` 目前顺序是:R2 写缓存 → world_cache 入库 → 置 completed。若结算失败,缓存已落,他人/本人可经「拉取半价」用掉,存在泄露。

### 目标
1. 删除旧预扣任务结算退款逻辑。
2. 运行中只记账不扣费;**任务成功完成时一次性扣实际消耗 tokensUsed**。
3. 结算时余额不足 → 任务转 `paused`(已完成待结算),**不写共享缓存、不可下载**;充值后「继续任务」补扣成功 → 写缓存 → 置 completed。

### 服务端改动(server/utils/world-gen-pipeline.ts)
- **`recordTaskUsage`(L174-203)**:删平台逐笔扣余额分支(L177-185),只记账(ai_usage + tokensUsed 增量)。不再抛 `InsufficientTokensError`。
- **新增 `settleTaskOnSuccess(ctx)`**:
  - `keySource==='user'` 或 `tokensUsed<=0` → true(自建 key 零扣费);
  - `estimatedTokens===0` → true(已结算幂等标记,防重跑双扣);
  - 否则原子扣 `aiTokenBalance -= tokensUsed`(条件 balance>=tokens);扣不动 → `markTaskPaused`(error:「任务已完成但 token 余额不足,充值后点击「继续任务」完成结算」)+ false;
  - 扣成功 → `markTask({ estimatedTokens: 0 })` 幂等标记 + true。
- **`stepFinalize`(L963-1042)重排序**:
  1. 读 scratch、组装 payload(不变);
  2. **先 `settleTaskOnSuccess`**,false → 直接 return(不写 R2、不入 world_cache、不置 completed,结果只留在 scratch,任务已转 paused);
  3. 结算成功后才 `bucket.put(resultKey)` + world_cache upsert(非 custom 模式);
  4. `markTask({ status:'completed', resultKey, ... })` → clearTaskKey → cleanupScratch;
  5. 开头加 `status==='completed'` 幂等短路。
  - 重试安全:若上次已结算(estimatedTokens 已清零)但 put/入库前中断,重跑时 settle 直接 true,put 与 upsert 本身幂等,不会双扣。
- **`stepSupplementArcs` 两个 arcs completed 分支(L816-820 / L932-940)**:置 completed 前先 `settleTaskOnSuccess`,false → 不置 completed(结果留在 scratch,`/arcs` 读取接口因非 completed 不可用);world 成书分支不动(finalize 统一结算)。
- **删除 `settleTaskBilling`(L209-229)** 及 4 处调用:
  - `markTaskFailed`(L242):去结算,保留 clearTaskKey;
  - `sweepStaleWorldGenTasks`(L269):孤儿超时判失败不再结算(运行中没扣费,失败即免费);
  - `stepFinalize`(L1031):被 settleTaskOnSuccess 取代;
  - `tasks/[id].delete.ts`(L27):取消不再结算(失败/取消一律不扣费)。
- **`resume.post.ts`**:余额判定区分——`stage==='done'`(已完成待结算)需 `balance >= tokensUsed`;历史断点暂停需 `balance >= max(1, estimatedTokens - tokensUsed)`。流程不变:置 running → startWorldGenTask 重跑(检查点全命中,直达 finalize 结算→写缓存→completed)。
- **`server/db/schema.ts`**:更新 `reserveTaken`/`estimatedTokens` 注释(列保留;estimatedTokens 结算后清零=幂等标记)。**无数据库迁移**。
- **缓存隔离确认**:world_cache 只在结算成功后 upsert,`upload.post.ts` 的 cacheHit 查询永远碰不到未结算产物;download 接口本就要求 `completed && resultKey`,结算前 resultKey 未写 → 409。arcs 结果同理(非 completed 不可读)。

- 自建 key:只记账,结算直接通过。
- pull.post.ts 独立半价即时扣费不动(它拉的缓存行必然来自已结算任务)。
- 客户端运行中实时 token 展示照常(tokensUsed 实时累计,完成时才扣余额)。
- `InsufficientTokensError` 类与 workflow/inline 顶层 paused 捕获保留(防御)。
