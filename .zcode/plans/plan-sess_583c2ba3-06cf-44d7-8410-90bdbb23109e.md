## 管理后台「站内邮件」功能(管理员给用户发真实邮件)

**说明**:「站内邮件」= 管理员在后台选择注册用户作为收件人,通过已有的 Cloudflare Email Service 邮件机制发送真实邮件(与验证码同一通道)。复用现成:邮件发送(server/utils/email.ts)、用户搜索(/api/admin/users?q=)、admin 布局与鉴权中间件。

### 1. 通用邮件发送函数(server/utils/email.ts)
- 现有 `sendOtpEmail` 模板写死(OTP 专用)。新增通用 `sendEmail({ to, subject, html, text, ctx })`,复用 `getEmailCtx`(env→runtimeConfig)、Cloudflare REST 端点与 dev 降级(未配置 token 时打印日志)逻辑。
- 重构 `sendOtpEmail` 调用 `sendEmail`(签名与行为不变,不破坏 auth.ts 调用方)。

### 2. 发送历史表(server/db/schema.ts + drizzle/init.sql)
新增 `mail_sent` 表(遵循项目迁移约定:init.sql 幂等 CREATE TABLE IF NOT EXISTS + 索引,不跑 drizzle-kit generate):
- `id`(text PK,uuid)、`sender_id`(管理员 user.id)、`recipient_id`(user.id)、`recipient_email`/`recipient_name`(快照,防用户改邮箱后历史展示丢失)、`subject`、`content`、`status`('sent'|'failed')、`error`(失败原因,可空)、`created_at`
- 索引:`idx_mail_created`(created_at)、`idx_mail_recipient`(recipient_id)
- 迁移:`pnpm db:migrate:local`(本地)/ `db:migrate:remote`(部署时)

### 3. 管理 API(server/api/admin/,沿用 admin-auth.ts 全局鉴权 + 每题 requireAdmin)
- **`GET /api/admin/mail`** — 历史发送记录列表(分页,按时间倒序)。
- **`POST /api/admin/mail/send`** — body `{ recipientIds: string[], subject: string, content: string }`:
  - 校验:收件人 ≥1、subject/content 非空且设上限(如 subject ≤200、content ≤10000);
  - 逐收件人查 `user` 表拿邮箱 → 逐个 `sendEmail`,每个独立 try/catch 并写一条 `mail_sent`(成功 status='sent',失败 status='failed' + error);
  - 一封失败不影响其他;返回逐封结果 `{ sent, failed, results: [{ email, ok, error }] }`。

### 4. 管理页面(app/pages/admin/mail.vue)
`definePageMeta({ layout: 'admin', middleware: 'admin' })`,仿 announcements.vue 风格,两块:
- **发送表单**:
  - 收件人搜索:UInput(300ms 防抖)→ `GET /api/admin/users?q=` 返回候选(昵称+邮箱),点击加入已选收件人标签列表(UBadge 可移除),支持多选;
  - 主题 UInput + 内容 UTextarea(自由输入);
  - 「发送」按钮 → POST `/api/admin/mail/send` → toast 汇总(成功 N 封 / 失败 M 封,失败展开明细)。
- **发送历史**:原生 table 列出时间、收件人、主题、状态徽章(成功/失败),失败行显示错误。

### 5. 侧边栏入口(app/layouts/admin.vue)
items 数组追加 `{ label: '站内邮件', icon: 'i-lucide-mail', to: '/admin/mail', active: route.path === '/admin/mail' }`。

### 6. 验证
- eslint + typecheck + `pnpm test`。
- 本地 dev:登录管理员 → 进入站内邮件 → 搜索 testuser → 添加收件人 → 输入主题/内容 → 发送成功(dev 下 token 未配走日志降级,history 显示 sent)→ 历史列表可见。若 `.dev.vars` 已配真实 token 则真实发信。

### 不变的部分
- 用户侧无需新增收信页面(用户通过真实邮箱收信)。
- 验证码/登录流程不受影响(sendOtpEmail 行为不变)。
- 无前端用户侧改动。
