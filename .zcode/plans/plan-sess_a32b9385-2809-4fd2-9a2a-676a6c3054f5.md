# Skill 商城 + 管理后台改造 实施方案(修订:本地直连云端 R2)

## 目标
1. **Admin 单独 layout + 左侧侧边栏**,三入口:兑换码管理(现有,搬迁)、充值记录(新增)、Skill 审核(新增)。
2. **Skill 商城**:导航栏入口(`/store`),游客可浏览;token 作货币购买,购后永久可下载;登录用户可发布 skill(zip,标准 agent skill 格式),管理员审核通过后上架。
3. **收益分成**:售价 80% 直接进发布者余额,20% 平台手续费(发布页注明)。
4. **优质 skill 推荐标识**(管理员打标,商城显示徽章)。

## 已确认决策
- 游客可浏览商城;购买/发布需登录。
- **skill zip 存 R2,本地 dev 直连云端 R2**(与现有 D1 `remote = true` 同款 Remote Bindings 方案)。

## Phase 1 — 基础设施

**新增依赖**:`fflate`(纯 JS zip 解析)——上传时校验 zip 完整性、确认含 `SKILL.md`、提取文件清单供管理端预览。

**R2 绑定**(`wrangler.toml` 追加,复制 D1 的同款 remote 模式):
```toml
[[r2_buckets]]
binding = "SKILL_FILES"
bucket_name = "ai-spankworld-skill-files"
remote = true   # 本地 = 直接读写云端 bucket(与 D1 remote=true 一致,需 wrangler 登录态,npx wrangler whoami 可查)
```
- 一次性创建生产 bucket:`npx wrangler r2 bucket create ai-spankworld-skill-files`。
- `npx wrangler types` 重新生成 worker-configuration.d.ts(已含 R2 类型)。
- 服务端统一经 `event.context.cloudflare.env.SKILL_FILES` 访问。

**数据表**(追加 `server/db/schema.ts` + `drizzle/init.sql`,幂等 `CREATE TABLE IF NOT EXISTS`;运行中库 `pnpm db:migrate:remote`):
- `skill_products`:`id, seller_id(FK user), name, desc, price(int token), file_key(R2 key: skills/<sellerId>/<id>.zip), file_name, file_size, file_entries(JSON 文件清单), status(pending|approved|rejected|removed), reject_reason, featured(0/1), download_count, purchase_count, reviewed_by, reviewed_at, created_at, updated_at` + 索引(seller_id, status)。
- `skill_purchases`:`id, skill_id(FK cascade), buyer_id(FK cascade), price, seller_share, platform_fee, created_at` + **唯一索引(skill_id, buyer_id)** → 一次购买、永久下载、不可重购。

**共享常量**(新增 `shared/store-skill.ts`):`SELLER_RATIO=0.8 / PLATFORM_RATIO=0.2`、`MAX_SKILL_ZIP_MB`(10)、`MIN_SKILL_PRICE`(1000)、状态枚举、类型、`normalizeZipEntries()` 等。

## Phase 2 — 服务端 API
**Store**:
- `GET /api/store/skills` — 公开;已审核列表(名称/说明/发布用户名/价格/featured/下载数/购买数/时间),翻页。
- `POST /api/store/skills` — 发布(requireUser,multipart):name/desc/price/zip;zip 魔数 `PK` + fflate 校验含 `SKILL.md` + 大小上限;写 R2,建 `skill_products(status=pending)`。
- `POST /api/store/skills/[id]/purchase` — 购买(requireUser):禁自购;沿用 redeem 原子模式——条件扣款 `UPDATE user SET ai_token_balance = ai_token_balance - price WHERE id=:buyer AND ai_token_balance >= price`(0 行→402),batch 内 `seller.ai_token_balance += round(price*0.8)`、记 20% 平台费、插 `skill_purchases`;已购幂等返回。
- `GET /api/store/skills/[id]/download` — 已购者或管理员;R2 流式返回(Content-Disposition attachment),`download_count+1`。
- `GET /api/store/mine` — (requireUser)我的购买(可再下载)+ 我的发布(审核状态/拒绝原因)。

**Admin**(均 requireAdmin):
- `GET /api/admin/recharge/list` — 全部 `quota_package_order` LEFT JOIN user,状态筛选 + 分页,倒序(充值记录审计页)。
- `GET /api/admin/skills` — 全部 skill + 发布者信息,状态筛选(pending 优先)。
- `POST /api/admin/skills/[id]/review` — `{ status?: 'approved'|'rejected', reason?, featured? }`:通过/拒绝(原因)/推荐开关;写 reviewed_by/reviewed_at。

## Phase 3 — Admin 布局与页面
- **`app/layouts/admin.vue`**:Nuxt UI v4 `USidebar`(`left`,`collapsible="icon"`)+ `UNavigationMenu`,菜单:兑换码管理 /admin、充值记录 /admin/recharge、Skill 审核 /admin/skills;顶部返回主站;内容 `<slot />`(不套 default layout,去掉全站 header/footer)。
- **`app/pages/admin.vue` → `app/pages/admin/index.vue`**(删旧单页):内容搬迁,`definePageMeta({ layout:'admin', middleware:'admin' })`。
- **`app/pages/admin/recharge.vue`**:充值记录表(用户/邮箱/套餐/金额元/支付方式/状态/支付时间/单号 + 状态筛选/分页)。
- **`app/pages/admin/skills.vue`**:skill 审核列表(名称/发布者/价格/状态/上传时间/文件清单/下载审核),操作:通过/拒绝(填原因)/推荐开关。

## Phase 4 — 商城前端 + 导航
- **`app/pages/store/index.vue`**(`/store`):三 Tab——全部(skill 卡片:名称/说明/发布用户名/价格/`推荐`徽章/购买或下载按钮)、我的购买(re-download)、我的发布(审核状态)。购买按钮未登录走现有 AuthModal(`useAuthModal`)。
- **`app/pages/store/publish.vue`**(`/store/publish`):发布表单(名称/说明/价格/上传 zip),显著注明 **"售出后您获得售价的 80% token,20% 为平台手续费;收益直接进入您的余额"**;提示格式要求(须含 SKILL.md)。
- **`app/middleware/auth.global.ts`**:`PUBLIC_PREFIXES` 加 `'/store'`(游客浏览);`/store/publish` 页面内用 `useAuthSession` 登录强校验(未登录 → `/login?redirect=/store/publish`)。
- **`app/layouts/default.vue`**:UHeader `#right` 加"Skill商城"按钮(`/store`,i-lucide-store),footer 同步加链接。

## 验证与上线
1. `pnpm add fflate`;`npx wrangler types`。
2. 按全局规则查 4569 端口占用(占用则杀旧),启动 dev。
3. 一次性:`npx wrangler r2 bucket create ai-spankworld-skill-files`。
4. 迁移:`pnpm db:migrate:remote`。
5. 手动验证:发布→管理审核(通过/推荐)→商城可见/购买→余额 80/20 入账→下载;充值记录页、兑换码搬迁后正常。**同时确认 R2 上传/下载打到云端真桶**(控制台可查到对象)。
6. 完成后关掉自己起的 dev server 并确认端口释放。
