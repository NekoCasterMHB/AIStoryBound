## 目标

把"按作品整包备份"变成唯一的云端同步方式：本地作品点击「同步云端」→ 将作品 + 其全部游戏会话 + 存盘点打包成一个 ZIP 上传 R2，D1 记录元数据；书架原有「云端作品」「云端游戏」两个区块合并为统一的「云端备份」列表；上传前查询同 id 是否传过、传过则显示上次上传时间并弹覆盖确认；下载时取回 ZIP 自动解压导入本地。

**已确认的三个决策（按推荐默认）**：
1. 完全替换旧同步：移除按回合自动同步开关（个人中心 + 游戏页）、`/api/works` 与 `/api/games` 的客户端调用；旧云端数据保留在 D1 但不再展示。
2. 备份包 = LocalWork（含章节正文/世界观/细纲）+ 该 workId 的全部 LocalGame + 每局对应的 GameSavePoint。
3. 下载冲突：作品同 id 已存在 → 弹「覆盖/保留现有」确认；游戏与存盘点同 id 直接覆盖（云端为权威），本地独有的游戏保留。

## 1. 云端：D1 新表 + R2 存储

**`server/db/schema.ts` 新增 `work_backups` 表**：
- `id` text PK（uuid）、`userId`、`workId`、`title`、`r2Key`、`sizeBytes`、`gameCount`、`messageCount`、`workUpdatedAt`（上传时本地 work.updatedAt，用于"有更新待同步"）、`uploadedAt`（上次上传时间，覆盖提示显示）
- 索引：`idx(userId)` + `unique(userId, workId)`

**R2 键**：`backups/<userId>/<workId>.zip`。同 key 反复 `put` 即覆盖旧对象（等效"删除旧 zip"），复用现有 `SKILL_FILES` 桶（`getSkillBucket`），无需改 wrangler.toml。

**新增 `server/utils/backup-db.ts`**：`getBackup` / `listBackupsByUser` / `upsertBackup` / `deleteBackup`（沿用 game-db.ts 的 H3Event + drizzle 模式）。

**新增 5 个端点（全部 `requireUserId` + 归属校验，404 不泄露存在性）**：
- `POST /api/backups/upload`：multipart（`meta` JSON + `file` zip 二进制，≤64MB 守卫）→ upsert D1 记录 + R2 put → 返回 `{ uploadedAt }`
- `GET /api/backups`：当前用户备份列表 `{ workId, title, uploadedAt, workUpdatedAt, gameCount, sizeBytes }`（按 uploadedAt 倒序）
- `GET /api/backups/[workId]`：单条记录或 404（"是否传过"预查，返回上次上传时间）
- `GET /api/backups/[workId]/download`：R2 get → 返回 `application/zip` 字节
- `DELETE /api/backups/[workId]`：删 R2 对象 + D1 记录（合并列表的配套操作）

**迁移**：schema 加表后 `pnpm db:generate` 生成迁移文件，`db:migrate:local` 本地应用，`db:migrate:remote` 部署时应用（远程 D1 改动会单独提示确认）。

## 2. 客户端：打包与解析

**`shared/share-format.ts` 新增**：`BACKUP_FORMAT = 'aisb-backup'`、`BACKUP_VERSION = 1`、`BackupManifest { format, version, kind:'work-backup', workId, exportedAt, gameCount }`。ZIP 条目：`manifest.json` / `work.json` / `games.json` / `saves.json`（fflate `zipSync/unzipSync`，客户端构建，沿用 shareZip 的 manifest 校验范式）。

**新增 `app/utils/backupStore.ts`**：
- `buildWorkBackupZip(workId)`：`getWork` + `listLocalGames().filter(workId)` + 每局 `listGamePoints` → 组装 zip + meta（含 size/gameCount）
- `parseWorkBackupZip(bytes)`：unzipSync → 校验 manifest → 返回 `{ work, games, saves }`；work 保留原 id（与 shareZip 的 `normalizeWork` 不同，不清 id、不重造 uuid），`syncStatus='synced'`
- `fetchBackups()` / `fetchBackupMeta(workId)` / `uploadWorkBackup(zip, meta)` / `downloadWorkBackup(workId)`

## 3. 书架 UI（app/pages/works.vue）

- **删除**：`cloudWorks`/`cloudGames` 两个区块及其加载/恢复函数（`loadCloudWorks`、`restoreFromCloud`、`loadCloudGames`、`restoreCloudGame`、`syncWorkToCloud`）。
- **新增「云端备份」区块**（原两区块位置）：卡片显示作品标题、`最后上传: fmtTime(uploadedAt)`、`N 个游戏会话`、大小；按钮「下载到本机」「删除备份」（删除走现有 UModal 确认模式）。
- **每作品菜单「同步云端」改为新流程**：① `fetchBackupMeta(work.id)`，存在 → 弹覆盖确认（复用现有 Promise 式 UModal 模式，正文显示"上次上传时间: …"）→ 确认后；② `buildWorkBackupZip` → `uploadWorkBackup` → 成功置 `syncStatus='synced'` + `saveWork` + 刷新云列表 + toast。
- **「下载到本机」**：`downloadWorkBackup` → `parseWorkBackupZip`；本地已存在同 id 作品 → 覆盖弹窗（保留现有则跳过作品、仍导入游戏）；游戏/存盘点同 id 覆盖写入、本地独有保留；`refreshLocal` + toast。
- 本地作品卡：同步徽标沿用 `syncStatus`；有备份且 `work.updatedAt > backup.workUpdatedAt` 时显示"有更新待同步"。

## 4. 移除旧同步

- `app/utils/cloudSave.ts` 删除；`profile.vue` 的「云端同步」开关卡片删除。
- `app/pages/games/[id].vue`：删除 `cloudSaveEnabled` 引用、3 处自动同步调用、手动同步按钮。
- `app/utils/gameStore.ts`：删除 `syncGameToCloud`（及 gzip import）。
- 服务端 `/api/works/*`、`/api/games/*` 端点**保留但不改**（客户端不再调用；删除它们有外部破坏风险，故不动）。

## 5. 验证

- `pnpm typecheck` + `pnpm test` 通过。
- 手动走查：上传含游戏/存盘点的作品 → 检查 D1 行与 R2 对象；再次上传 → 覆盖提示显示上次时间；下载到本机 → 自动解压导入，继续游戏、存盘点、选项、段位全部还原。
- 本地 dev（D1 local + R2 local 模拟）跑通后，`db:migrate:remote` 需确认后执行。
